# ⚡ Завдання 1. Оптимізація доступу до даних за допомогою LRU-кешу

## 📖 Опис задачі

У даному завданні реалізовано систему обробки запитів до великого масиву чисел.

Для підвищення продуктивності використовується алгоритм **LRU Cache (Least Recently Used)**, який дозволяє зберігати результати популярних запитів та уникати повторних обчислень.

---

## ⚙️ Реалізація

- `range_sum_no_cache()` — обчислення суми без кешування
- `update_no_cache()` — оновлення елемента масиву
- `range_sum_with_cache()` — обчислення суми з використанням LRU-кешу
- `update_with_cache()` — оновлення елемента та інвалідація кешу
- `LRUCache` — реалізація кешу на основі `OrderedDict`

---

## 🧠 Принцип роботи

1. Генерується масив із 100 000 випадкових чисел.
2. Створюється 50 000 запитів типів:
   - `Range(L, R)`
   - `Update(index, value)`
3. Запити виконуються без кешу.
4. Запити виконуються з використанням LRU-кешу.
5. Порівнюється час виконання обох підходів.

---

## 📊 Результати виконання

Приклад результату:

| Метод | Час (сек) |
|--------|-----------|
| Без кешу | 12.45 |
| LRU-кеш | 4.79 |
| Прискорення | ×2.6 |

---

## 📌 Висновок

Використання LRU-кешу дозволяє значно пришвидшити обробку повторюваних запитів за рахунок збереження раніше обчислених результатів.

# 🚦 Завдання 2. Rate Limiter на основі Sliding Window

## 📖 Опис задачі

У чат-системі реалізовано механізм обмеження частоти надсилання повідомлень користувачами.

Для контролю використовується алгоритм **Sliding Window**, який дозволяє точно відстежувати кількість запитів у заданому часовому інтервалі.

---

## ⚙️ Реалізація

Клас `SlidingWindowRateLimiter` містить такі методи:

- `_cleanup_window()` — очищення застарілих повідомлень
- `can_send_message()` — перевірка можливості надсилання повідомлення
- `record_message()` — запис нового повідомлення
- `time_until_next_allowed()` — обчислення часу очікування

Для зберігання історії повідомлень використовується структура даних `deque`.

---

## 🧠 Принцип роботи

1. Для кожного користувача зберігається список часових міток повідомлень.
2. Перед кожною перевіркою видаляються застарілі записи.
3. Якщо кількість повідомлень у вікні менша за ліміт — повідомлення дозволяється.
4. Якщо ліміт перевищено — повертається час очікування до наступної дозволеної відправки.

---

## 📊 Результати виконання

Програма демонструє:

- успішне надсилання першого повідомлення;
- блокування повторних повідомлень протягом 10 секунд;
- автоматичне розблокування після завершення вікна;
- коректний розрахунок часу очікування.

Приклад виводу:

```text
=== Симуляція потоку повідомлень ===
Повідомлення 1 | Користувач 2 | ✓
Повідомлення 6 | Користувач 2 | × (очікування 7.4с)

=== Нова серія повідомлень після очікування ===
Повідомлення 16 | Користувач 2 | ✓
```
